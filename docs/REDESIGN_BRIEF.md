# Front-end redesign brief

**Status:** superseded. Written 2026-08-22 as the plan for the next session; a
different direction (conservation-editorial, Swiss-modernist) was chosen and shipped
instead — see `design-system/wangdi-portfolio/MASTER.md` for the design system that is
actually live. This document is kept because the elevation-figure research below (the
one part of it still true) is worth having on hand if a future pass wants to use
altitude as a device — e.g. a literal elevation plot on `/publications`, which the real
per-study ranges would support.

This is a **redesign, not a refinement**. The owner previously chose "refine, don't
redesign" and that decision has been reversed — the old look is evidence and
anti-reference, not something to preserve. Product truth, content, URLs, and the rights
constraints below are not up for redesign.

## Direction: elevation gradient

Altitude is the organising device for the whole site.

This is not decoration borrowed from generic "forest" imagery. Elevation is the axis
Wangdi's own research is repeatedly structured by, and every figure below is quoted from
the site's own content:

| Range | What it is | Source |
| --- | --- | --- |
| 64–2,552 m | Elevational gradient of the mammalian community-assembly study | `src/content/publications/community-assembly.md` |
| 260–1,964 m a.s.l. | 220 vegetation plots, subtropical to cool broadleaved forest | `src/content/publications/vegetation-community.md` |
| 800–1,200 m | Diversity stratum, H′ = 2.36 | `src/content/publications/aquatic-beetles.md` |
| 1,000–4,000 m | Forest-carbon elevation belt | `src/content/publications/forest-carbon-sequestration-cmip6.md` |

The working span across the portfolio is therefore roughly **64 m to 4,000 m**, with the
dense band between **260 m and 2,552 m**. Use these real numbers. Do not invent generic
Bhutan forest zones — the credibility of the device depends on the figures being his.

Approved concept sketch:

```
  4500m ┤▒▒ alpine scrub
        │
  3200m ┤▓▓▓▓ fir · hemlock        WANGDI
        │                          Senior Forestry Officer,
  2100m ┤████████ broadleaf        Department of Forests
        │                          & Park Services
  1200m ┤██████████ warm broadleaf
        │                          ┌─────────────────┐
   300m ┤████████████ subtropical  │  18 outputs     │
        └──────────────────────────┴─────────────────┘
         sections anchor to the band they belong to
```

Open design questions for the build (decide in `new-work`, then record in `DESIGN.md`):

- Whether the elevation axis is a persistent page-edge rail or appears per section.
- Whether ground stays dark. The direction does not require it; the brief only pins
  altitude as the device.
- How sections map to bands. A forced mapping would be dishonest — some content
  (Code, Contact) has no elevation. Decide what those do rather than faking a height.
- Mobile: a vertical axis competes with a vertical page. Solve this early, not last.

## Hard constraints

**URLs must not change.** `scripts/check-routes.mjs` requires, for every content entry, a
canonical extensionless route *and* a legacy `<slug>.md/` redirect carrying `noindex` plus
a root-relative canonical. `npm run check:routes` runs in CI before the artifact upload, so
breaking this blocks deployment. Legacy redirects are generated by
`scripts/write-legacy-redirects.mjs` via the `postbuild` hook.

**Design tokens are generated.** `src/styles/tokens.css` is written by
`scripts/build-tokens.mjs` from `tokens/tokens.json`, and `prebuild` regenerates it on every
build. Editing `tokens.css` directly is silently discarded. All colour and type changes go
in `tokens.json`, then `npm run tokens`.

Note the flattening bug already fixed here: nesting a group inside `color` produces
`--color-<group>-<name>`. Semantic tokens must sit directly under `color`.

**Rights are binding.** `docs/RIGHTS.md` governs which PDFs and images may be hosted.
Map layers remain gated on DoFPS clearance (`docs/GEODATA.md`); `src/data/geo/layers.json`
is empty by design and an unregistered file in `public/geo/` fails the build. A redesign
that wants a real elevation map cannot invent one — it needs cleared data or a
non-geographic abstraction.

**Budgets.** `scripts/check-budgets.mjs` caps `public/publications/` at 60 MB total with a
per-file default of 2 MB and a named exceptions list.

## Already done — do not redo

- **Gallery curated** 34 → 16. Duplicates, a Facebook collage template, and off-topic
  frames removed; six files had letterbox bands cropped off with sharp. All 16 carry real
  descriptive alt text in `src/data/gallery.ts`, keyed by filename. **Filenames are
  load-bearing keys — do not rename.**
- **Hero portrait replaced** with `src/assets/wangdi-dfo-sarpang.jpg` (Wangdi in uniform at
  the Divisional Forest Office gate), desaturated and blended into the page ground. The old
  white-background ID portrait is deleted.
- **Publications filter** is drawn as the real pipeline: in-preparation → under-review →
  published, with plans and strategies as a separate track. Keep this semantic if the
  visuals change — it encodes something true.
- **Contact** is a label/value record rail; **case-study cards** bottom-align their method
  pills; **About/Contact headings** are sticky on `lg`.
- **Gallery lede** rewritten to match what the photographs actually show. It previously
  claimed camera traps, inventory, and telemetry that appear in none of them.

Contrast was measured on the current palette and all pairs pass WCAG AA against `ink-900`
(`paper-50` 16.42:1, `slate-400` 5.18:1, `moss-400` 7.02:1, `amber-500` 7.88:1). If the
palette changes, re-measure — do not assume.

## Session setup

The design plugins load **only at session start**. Confirm `impeccable` and the
`ui-ux-pro-max` skills appear in the available-skills list before relying on them; if
`/design` returns "Usage: /design consent | /design revoke" that is DesignSync, not the
skill, and they have not loaded.

1. Run `/impeccable init` to scaffold `PRODUCT.md` and `DESIGN.md`.
2. Work through impeccable's `new-work` path — this is a replacement visual world, which is
   what that path is for. Transfer this brief into `DESIGN.md` so the elevation direction
   and the real figures are pinned before any editing.
3. Record in `DESIGN.md` that `tokens.css` is generated and must never be hand-edited.

Two gotchas:

- **`banner-design` collides.** `ui-ux-pro-max` ships a skill of that name and a personal
  one already exists at `~/.claude/skills/banner-design`. Check which resolves before use.
- **impeccable installs auto-firing hooks** — `PostToolUse` on `Edit|Write` (5s) and `Stop`
  (30s). Every edit and turn gets slower. `claude plugin disable impeccable@impeccable`
  turns them off.

`ui-ux-pro-max`'s palette and font-pairing databases are now genuinely useful, since the
palette is no longer fixed. Its `brand` and `design-system` skills are still redundant with
the existing token pipeline.

## Verification

`npm run verify` is the gate — tests, then `prebuild` (tokens, budgets, geo), build,
`postbuild` redirects, and `check:routes`.

Additionally:

1. `ls dist/publications | grep '\.md'` returns nothing beyond the intended redirect
   directories, and `dist/rss.xml` and `dist/sitemap-0.xml` contain no `.md/` URLs.
2. Re-measure contrast on every new colour pair; all text must clear 4.5:1.
3. Check mobile properly. `resize_window` did not change the captured viewport in the
   previous session — use Chrome DevTools device emulation or a real device against
   `npm run preview`.
4. Deploy is CI-gated; confirm the Actions run is green before treating it as shipped.
